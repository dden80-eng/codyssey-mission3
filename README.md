# 그림 판별 숫자 계산기 (Mini NPU Simulator)

사람은 그림을 눈으로 보고 `+`(십자가)와 `X`를 바로 구별하지만, 눈이 없는 컴퓨터는 모든 그림을 **0(빈칸)과 1(색칠된 칸)이 적힌 '숫자 바둑판'**으로 바꾼 뒤 점수를 계산해서 맞힙니다.
이 프로그램은 인공지능 칩(NPU)이 그림을 알아보는 핵심 원리인 **'같은 칸끼리 곱하고 전부 더하기(MAC 연산)'**를 파이썬 기본 기능만으로 직접 구현한 시뮬레이터입니다.

---

## 1. 작업 준비 및 문제 파일(`data.json`) 구조 확인

- **실행 환경**: Python 3.8 이상 (외부 추가 도구 없이 파이썬 기본 기능만 사용)
- **파일 구성**: 실행 프로그램(`main.py`)과 문제 파일(`data.json`)을 같은 폴더(`codyssey-mission3`)에 배치했습니다.
- 프로그램을 짜기 전, 먼저 `data.json` 파일 안에 어떤 크기의 정답지와 문제가 들어 있는지 확인했습니다.

**▶ 실제 작업 화면 (`data.json` 내부 구조 확인)**
```text
필터: {'size_5': ['cross', 'x'], 'size_13': ['cross', 'x'], 'size_25': ['cross', 'x']}
패턴 개수: 6
size_5_1 -> 크기: 5 x 5 / 정답: x
size_5_2 -> 크기: 5 x 5 / 정답: +
size_13_1 -> 크기: 13 x 13 / 정답: x
size_13_2 -> 크기: 13 x 13 / 정답: +
size_25_1 -> 크기: 25 x 25 / 정답: x
size_25_2 -> 크기: 25 x 25 / 정답: +
```

## 3. 핵심 작동 원리 및 결과 리포트

### 3.1 핵심 구현 원리 요약
- **숫자 바둑판 점수 계산 (MAC 연산)**: 두 바둑판을 겹쳐 같은 칸의 숫자끼리 곱한 뒤 모두 더합니다. 모양이 비슷할수록 `1 × 1`이 많이 나와 점수가 높습니다.
- **이름표 통일 (라벨 정규화)**: 파일 안에 `'+'`, `'cross'`처럼 제각각 적힌 이름표를 프로그램 내부에서 **`Cross`**와 **`X`** 두 가지 표준 이름으로 통일했습니다.
- **소수점 미세 오차 보정 (허용오차 `1e-9`)**: 소수점 덧셈 시 생기는 미세한 오차(`0.000000001` 미만)는 사실상 같은 점수로 보고 무승부(`UNDECIDED`) 판정합니다.
- **불량 입력 방어**: 글자 오입력이나 바둑판 크기 불일치가 발생해도 프로그램이 강제 종료되지 않고 안내 문구 출력 또는 해당 문제만 `FAIL` 처리합니다.

### 3.2 왜 6문제 중 3문제가 실패(`FAIL`)로 나왔나요?
- **통과한 3문제 (`size_5_2`, `size_13_1`, `size_25_2`)**: 한쪽 점수가 압도적으로 높아 기대 정답(`Cross` 또는 `X`)과 정확히 일치(`PASS`)했습니다. 특히 `size_25_2`는 `52.899999999999986`처럼 미세한 소수점 오차가 있었지만 비교 규칙 덕분에 정상 통과했습니다.
- **실패한 3문제 (`size_5_1`, `size_13_2`, `size_25_1`) 원인 분석**: 프로그램 고장이 아니라, 두 정답지(`Cross`, `X`)에 대고 계산한 점수가 똑같거나 차이가 허용오차(`1e-9`) 미만으로 나와 **무승부(`UNDECIDED`) 판정**을 받았기 때문입니다. 점수가 같을 때 억지로 한쪽을 찍지 않는 규칙에 따라 기대 정답과 불일치하여 `FAIL`로 분류되었습니다.

### 3.3 바둑판 크기에 따른 계산 시간과 시간 복잡도 `O(N²)`
글자 입출력 시간을 제외하고 순수 계산 시간만 크기별 10회 반복 측정한 평균 결과입니다.

| 바둑판 크기 (N×N) | 총 계산 칸 수 (N²) | 평균 걸린 시간 (ms) | 3×3 대비 칸 수 배율 |
| :--- | :---: | :---: | :---: |
| **3×3** | 9칸 | 0.0006 ms | 1.0배 |
| **5×5** | 25칸 | 0.0012 ms | 2.8배 |
| **13×13** | 169칸 | 0.0059 ms | 18.8배 |
| **25×25** | 625칸 | 0.0186 ms | 69.4배 |

- **근거**: 가로 N칸, 세로 N칸 바둑판의 전체 칸 수는 항상 `N × N = N²`개입니다. 한 변이 `3칸`에서 `25칸`으로 커지면 계산 칸 수가 9칸에서 625칸으로 **69.4배** 늘어나고 실행 시간도 **약 31배** 함께 증가하므로 시간 복잡도는 **`O(N²)`**입니다.

## 4. 작업 과정 중 발생한 문제와 해결 기록

1. **소수점 미세 오차 문제**: `size_25_2` 계산 시 `52.899999999999986`처럼 끝에 미세한 소수점이 붙는 현상을 확인하고, 차이 `1e-9` 미만은 동점으로 간주하는 허용오차 정책을 적용해 해결했습니다.
2. **한글 글자 깨짐 오류 (`AttributeError`)**: 윈도우 터미널과 파이썬의 한글 인코딩 방식이 달라 빈 값이 반환되던 문제를 `PYTHONUTF8=1` 및 `PYTHONIOENCODING=utf-8` 설정으로 해결했습니다.
3. **명령어 창 입력 대기 멈춤(`>>`) 및 코드 잘림 현상**: 너무 긴 코드를 한 번에 붙여넣을 때 중간 기호나 길이 제한으로 명령어가 잘리던 문제를, 코드를 두 단계로 나누어 저장하고 특수 기호를 파이썬 코드로 생성하는 방식으로 개선했습니다.
4. **메뉴 및 바둑판 입력 실수 방어**: 숫자 대신 영문자(`s`)를 입력하거나 3×3 칸 수를 틀려도 프로그램이 꺼지지 않고 안내 문구 후 재입력받도록 검증 로직을 적용했습니다.
