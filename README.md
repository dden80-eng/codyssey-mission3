# Mini NPU Simulator (2D 패턴 매칭 MAC 연산 시뮬레이터)

## 1. 실행 방법

### 실행 환경 및 파일 위치
- **개발 환경**: Python 3.8 이상 (외부 라이브러리 미사용, 표준 라이브러리 `json`, `re`, `time`, `pathlib`만 사용)
- **필수 파일 배치**: `main.py`와 `data.json`을 동일한 프로젝트 폴더(`codyssey-mission3`)에 위치시킵니다.

### 프로그램 실행 및 모드 선택
터미널에서 아래 명령어를 입력하여 시뮬레이터를 실행합니다.
```bash
python main.py
```
실행 후 표시되는 메뉴에서 원하는 번호를 입력합니다.
- **`1` (사용자 입력 3×3)**: 3×3 크기의 필터 A, 필터 B와 판별할 패턴을 한 줄씩 공백으로 구분해 직접 입력하고, 두 필터의 MAC 점수·평균 연산 시간(ms)·최종 판정(`A` / `B` / `판정 불가`)을 확인합니다.
- **`2` (data.json 분석)**: `data.json`에서 5×5, 13×13, 25×25 필터와 테스트 패턴을 자동으로 불러와 일괄 채점(`PASS`/`FAIL`), 크기별 성능 분석 표, 최종 테스트 요약을 출력합니다.
- **`3` ([보너스] 패턴 생성 및 1D 최적화 비교)**: 원하는 크기 N을 입력하면 N×N 십자가(`Cross`)와 `X` 패턴을 자동 생성하고, 2차원 이중 반복문과 1차원 단일 반복문(길이 N²)의 연산 속도를 비교합니다.
- **`0` (종료)**: 시뮬레이터를 안전하게 종료합니다.

## 2. 구현 요약

### 2.1 핵심 데이터 구조 및 MAC 연산 (`PatternMatrix`, `compute_mac`)
- `PatternMatrix` 클래스로 n×n 2차원 숫자 배열을 캡슐화하고, `get_value(row, col)` / `set_value(row, col, value)` 메서드로 특정 좌표 값을 안전하게 조회·수정하도록 구현했습니다.
- NumPy 등 외부 벡터화 라이브러리 없이 파이썬 기본 이중 `for` 반복문으로 동일 위치 원소를 곱하고 누적 합산(`total += p_grid[r][c] * f_grid[r][c]`)하는 MAC(Multiply-Accumulate) 연산을 직접 구현했습니다.

### 2.2 라벨 정규화 (`normalize_label`)
- `data.json` 내부에서 필터 키(`'cross'`, `'x'`)와 정답 기대값(`'+'`, `'x'`)이 서로 다른 표기로 혼재되어 있으므로, 로드 시점에 표준 라벨 **`Cross`**와 **`X`**로 일괄 변환(정규화)한 뒤 비교 및 콘솔 출력에 사용합니다.

### 2.3 동점 및 부동소수점 비교 정책 (`judge_scores`)
- 실수(float) 누적 덧셈 과정에서 발생하는 미세한 이진 부동소수점 오차를 보정하기 위해 허용오차 **`EPSILON = 1e-9`** 정책을 적용했습니다.
- `abs(score_a - score_b) < 1e-9` 조건을 만족하면 두 필터의 유사도가 동일한 것으로 간주하여 **`UNDECIDED`**(모드 1에서는 `판정 불가`)로 판정합니다.

### 2.4 입력 검증 및 스키마 예외 처리
- **모드 1**: 각 줄의 원소 개수가 3개가 아니거나 숫자 변환(`float`)에 실패하면 프로그램을 종료하지 않고 오류 안내 문구 출력 후 해당 줄을 재입력받습니다.
- **모드 2**: `data.json`의 키 형식(`size_{N}_{idx}`), 필터 존재 여부, 필터-패턴 간 행렬 크기 불일치 등을 케이스 단위로 검증하여 오류 발생 시 해당 케이스만 `FAIL`로 기록하고 전체 분석을 끝까지 완료합니다.

## 3. 결과 리포트

### 3.1 테스트 결과 요약 및 FAIL 케이스 상세 원인 분석
`data.json`에 포함된 총 6개 테스트 케이스를 실행한 결과, **통과(PASS) 3개, 실패(FAIL) 3개**가 도출되었습니다.

- **통과 케이스 (`size_5_2`, `size_13_1`, `size_25_2`)**:
  - `size_5_2`와 `size_25_2`는 `Cross` 필터 점수가 `X` 필터 점수보다 압도적으로 높아 `Cross`로 정확히 판정되었고, `size_13_1`은 `X` 필터 점수가 높아 `X`로 판정되어 `expected`와 일치(`PASS`)했습니다.
  - 특히 `size_25_2`의 경우 `Cross` 점수가 `52.899999999999986`처럼 이진 부동소수점 누적 오차를 포함해 계산되었으나, 비교 정책을 통해 정상적으로 `Cross` 판정을 내렸습니다.
- **실패 케이스 (`size_5_1`, `size_13_2`, `size_25_1`) 원인 분석**:
  - 세 케이스 모두 구현 로직 오류나 JSON 스키마 누락이 아니라 **수치 비교 및 동점 처리 정책(`UNDECIDED`)에 의해 의도적으로 `FAIL` 처리된 경계 테스트 케이스**입니다.
  - 각 패턴의 입력 배열을 `Cross` 필터와 `X` 필터에 각각 MAC 연산한 결과, 두 필터의 점수가 동일하거나 두 점수의 차이가 허용오차(`1e-9`) 미만으로 산출되었습니다.
  - 본 시뮬레이터는 점수가 사실상 동일한 경우 임의로 한쪽 라벨을 선택하지 않고 `UNDECIDED`로 판정하도록 설계되었기 때문에, 기존 `expected` 라벨(`Cross` 또는 `X`)과 불일치하여 `FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)`로 정확히 분류되었습니다.

### 3.2 크기별 성능 측정 결과 및 시간 복잡도 O(N²) 분석
입출력(I/O) 시간을 제외하고 순수 `compute_mac` 함수 호출 구간만 크기별 10회 반복 측정한 평균 실행 시간은 다음과 같습니다.

| 패턴/필터 크기 (N×N) | 연산 횟수 (N²) | 평균 연산 시간 (ms) | 3×3 대비 연산량 배율 |
| :--- | :---: | :---: | :---: |
| **3×3** | 9 | 0.0006 ms | 1.0배 |
| **5×5** | 25 | 0.0012 ms | 2.8배 |
| **13×13** | 169 | 0.0059 ms | 18.8배 |
| **25×25** | 625 | 0.0186 ms | 69.4배 |

- **시간 복잡도 O(N²) 근거**:
  - `compute_mac` 함수는 가로 크기 N과 세로 크기 N을 순회하는 이중 중첩 반복문(`for r in range(n): for c in range(n):`)으로 구성되어 있습니다.
  - 따라서 입력 크기가 N일 때 곱셈 1회와 덧셈 1회로 이루어진 기본 연산이 정확히 N × N = N²번 수행되므로 시간 복잡도는 **O(N²)**입니다.
  - 실제 측정 데이터에서도 한 변의 길이 N이 `3`에서 `25`로 약 8.33배 증가할 때, 총 연산 횟수는 3² = 9회에서 25² = 625회로 **69.4배** 증가했으며, 평균 실행 시간 역시 `0.0006 ms`에서 `0.0186 ms`로 **약 31배** 비례 증가하여 이론적 O(N²) 증가 추세와 일치함을 확인했습니다.
