# 그림 판별 숫자 계산기 (Mini NPU Simulator)

사람은 그림을 눈으로 보고 `+`(십자가)와 `X`를 바로 구별하지만, 눈이 없는 컴퓨터는 모든 그림을 **0(빈칸)과 1(색칠된 칸)이 적힌 '숫자 바둑판'**으로 바꾼 뒤 점수를 계산해서 맞힙니다.
이 프로그램은 인공지능 칩(NPU)이 그림을 알아보는 핵심 원리인 **'같은 칸끼리 곱하고 전부 더하기(MAC 연산)'**를 파이썬으로 직접 구현한 시뮬레이터입니다.

---

## 1. 실행 방법

### 실행 전 준비
- **사용 도구**: Python 3.8 이상 (별도의 추가 프로그램 설치 없이 파이썬 기본 기능만 사용합니다.)
- **파일 위치**: 실행 파일(`main.py`)과 문제 파일(`data.json`)을 같은 폴더(`codyssey-mission3`) 안에 나란히 넣어 둡니다.

### 프로그램 켜고 메뉴 고르기
검은 명령어 창(터미널)에서 아래 명령어를 입력해 프로그램을 실행합니다.
```bash
python main.py
```
화면에 메뉴가 나타나면 원하는 번호를 입력합니다.
- **`1` (내가 직접 3×3 바둑판 입력하기)**: 가로 3칸, 세로 3칸짜리 정답지 바둑판 2개(A, B)와 문제 바둑판 1개를 한 줄씩 직접 입력해 점수와 판정 결과(`A` / `B` / `판정 불가`)를 확인합니다.
- **`2` (문제 파일 `data.json` 한꺼번에 채점하기)**: `data.json` 안에 들어 있는 5×5, 13×13, 25×25 크기의 문제들을 자동으로 채점하고, 통과/실패(`PASS`/`FAIL`) 결과와 크기별 계산 속도 표를 보여줍니다.
- **`3` ([보너스] 바둑판 자동 생성 및 속도 비교)**: 원하는 크기(N)를 입력하면 `+`와 `X` 바둑판을 자동으로 만들고, 2차원 표 방식과 1줄로 펴서 계산하는 방식의 속도를 비교합니다.
- **`0` (종료)**: 프로그램을 안전하게 종료합니다.

## 2. 어떻게 만들었나요? (핵심 작동 원리)

### 2.1 숫자 바둑판 점수 계산 (MAC 연산)
- 추가 계산 도구를 빌려 쓰지 않고, 파이썬의 기본 반복문만으로 문제 바둑판과 정답지 바둑판을 겹쳐 **같은 위치에 있는 숫자끼리 곱한 뒤 모두 더합니다.**
- 두 그림의 모양이 비슷할수록 `1 × 1`이 많이 나와 **점수가 높게** 계산되고, 모양이 다를수록 **점수가 낮게** 나옵니다.

### 2.2 제각각인 이름표 하나로 통일하기 (라벨 정규화)
- `data.json` 파일 안에는 십자가 모양이 어떤 곳은 `'+'`, 어떤 곳은 `'cross'`처럼 서로 다른 이름으로 적혀 있습니다.
- 프로그램이 헷갈리지 않도록 파일을 읽어올 때 모든 이름표를 **`Cross`**와 **`X`** 두 가지 표준 이름으로 깔끔하게 통일한 뒤 비교합니다.

### 2.3 아주 미세한 소수점 차이는 '무승부'로 처리하기 (허용오차 `1e-9`)
- 컴퓨터는 소수점 숫자를 여러 번 더할 때 눈에 보이지 않을 만큼 아주 작은 계산 오차(예: `0.000000000000014`)를 내곤 합니다.
- 두 점수의 차이가 **`1e-9` (`0.000000001`)보다 작으면 사실상 똑같은 점수로 보고 무승부(`UNDECIDED`, 모드 1에서는 `판정 불가`)**로 판정합니다.

### 2.4 잘못된 입력이나 불량 문제가 들어와도 멈추지 않는 안전장치
- **직접 입력(모드 1)할 때**: 숫자가 아닌 글자를 치거나 한 줄에 3칸을 맞추지 않으면, 프로그램이 꺼지지 않고 안내 문구를 보여준 뒤 다시 입력받습니다.
- **파일 분석(모드 2)할 때**: 문제 파일 안에 바둑판 크기가 서로 안 맞는 불량 문제가 섞여 있더라도, 프로그램이 멈추지 않고 그 문제만 실패(`FAIL`)로 기록한 뒤 나머지 문제를 끝까지 채점합니다.

## 3. 결과 리포트 (채점 결과 및 속도 분석)

### 3.1 왜 6문제 중 3문제가 실패(`FAIL`)로 나왔나요?
`data.json`에 들어 있는 총 6문제를 채점한 결과, **통과(`PASS`) 3개, 실패(`FAIL`) 3개**가 나왔습니다.

- **통과한 3문제 (`size_5_2`, `size_13_1`, `size_25_2`)**:
  - `size_5_2`와 `size_25_2`는 `Cross` 점수가 `X` 점수보다 훨씬 높게 나와 `Cross`로 맞혔고, `size_13_1`은 `X` 점수가 높아 `X`로 정확히 맞혔습니다.
  - 특히 `size_25_2`는 `Cross` 점수가 `52.899999999999986`처럼 미세한 소수점 오차를 포함해 계산되었지만, 비교 규칙 덕분에 흔들림 없이 `Cross`로 통과했습니다.
- **실패한 3문제 (`size_5_1`, `size_13_2`, `size_25_1`)의 진짜 이유**:
  - 이 3문제가 실패한 이유는 프로그램 고장이나 파일 오류가 아니라, **두 점수가 똑같거나 차이가 거의 없어 무승부(`UNDECIDED`) 판정이 나왔기 때문**입니다.
  - 각각의 문제 바둑판을 `Cross` 정답지와 `X` 정답지에 대고 점수를 매겨본 결과, 두 점수가 완전히 같거나 차이가 기준치(`1e-9`)보다 작았습니다.
  - 우리 프로그램은 점수가 똑같을 때 억지로 한쪽을 찍지 않고 '판정 불가(`UNDECIDED`)'를 내리도록 약속되어 있으므로, 문제 파일에 적힌 기대 정답(`Cross` 또는 `X`)과 달라 규칙대로 `FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)`로 분류된 것입니다.

### 3.2 바둑판이 커질수록 계산 시간은 얼마나 늘어날까요? (시간 복잡도 `O(N²)`)
글자를 입력하거나 파일을 읽는 시간은 빼고, **순수하게 곱하고 더하는 계산 시간만 크기별로 10번씩 반복 측정한 평균 시간**입니다.

| 바둑판 크기 (N×N) | 총 계산 칸 수 (N²) | 평균 걸린 시간 (ms) | 3×3 대비 칸 수 배율 |
| :--- | :---: | :---: | :---: |
| **3×3** | 9칸 | 0.0006 ms | 1.0배 |
| **5×5** | 25칸 | 0.0012 ms | 2.8배 |
| **13×13** | 169칸 | 0.0059 ms | 18.8배 |
| **25×25** | 625칸 | 0.0186 ms | 69.4배 |

- **계산량이 제곱(`O(N²)`)으로 늘어나는 이유**:
  - 가로 N칸, 세로 N칸으로 이루어진 정사각형 바둑판의 전체 칸 수는 항상 **가로 N × 세로 N = N²개**입니다.
  - 따라서 바둑판 한 변의 길이가 `3칸`에서 `25칸`으로 약 8.3배 커지면, 실제로 곱하고 더해야 하는 칸 수는 9칸에서 625칸으로 **약 69.4배**나 훌쩍 늘어납니다.
  - 실제 측정 시간 역시 `0.0006 ms`에서 `0.0186 ms`로 **약 31배** 함께 증가했으며, 이처럼 **데이터의 한 변 길이가 늘어날 때 작업량이 그 제곱(N²)만큼 늘어나는 성질**을 시간 복잡도 **`O(N²)`**이라고 합니다.
