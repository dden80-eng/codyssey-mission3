# 그림 판별 숫자 계산기 (Mini NPU Simulator)

사람이 눈으로 `+`와 `X`를 구별하듯, 컴퓨터는 그림을 **0과 1의 숫자 바둑판**으로 바꾼 뒤 인공지능 칩(NPU)의 핵심 원리인 **MAC 연산(같은 칸끼리 곱하고 누적 더하기)**으로 모양을 판별합니다.

---

## 1. 작업 준비 및 `data.json` 구조 확인
- **실행 환경**: Python 3.8 이상 (외부 라이브러리 없이 표준 라이브러리만 사용)
- **파일 구성**: `main.py`와 `data.json`을 동일 디렉토리에 배치

**▶ 실제 작업 화면 (`data.json` 내부 구조 확인)**
```text
필터: {'size_5': ['cross', 'x'], 'size_13': ['cross', 'x'], 'size_25': ['cross', 'x']}
패턴 개수: 6
size_5_1 -> 크기: 5 x 5 / 정답: x
size_5_2 -> 크기: 5 x 5 / 정답: +
size_13_1 -> 크기: 13 x 13 / 정답: x
size_13_2 -> 크기: 13 x 13 / 정답: +
size_25_1 -> 크기: 25 x 25 / 정답: x
size_25_2 -> 크기: 25 x 25 / 정답: +
```

## 3. 핵심 원리 · 동점 정책 · 성능 분석 리포트

### 3.1 모드별 동점 처리 정책 및 규칙 변경 시 영향 범위
두 필터 점수 차이가 허용오차 `EPSILON = 1e-9` 미만일 때 동점으로 판정(`judge_scores`)하며, 모드별 우선 정책과 변경 시 영향 범위는 다음과 같습니다.

| 구분 | 모드 1 (사용자 입력) | 모드 2 (`data.json` 분석) |
| :--- | :--- | :--- |
| **우선 적용 정책** | `tie_label = "판정 불가"` 우선 적용 | `tie_label = "UNDECIDED"` 우선 적용 (`expected` 불일치로 `FAIL` 처리) |
| **동점 규칙 변경 시 영향 받는 출력** | `[3] MAC 결과`의 `판정:` 문자열 | 개별 케이스의 `판정:` 문자열 및 `FAIL` 사유 문구 |
| **동점 규칙 변경 시 영향 받는 집계** | 없음 (단일 입력 모드) | `[4] 결과 요약`의 **`통과` 개수, `실패` 개수, `실패 케이스` 목록** |

### 3.2 `data.json` 6개 케이스 중 3개 `FAIL` 원인 분석
- **통과 3건 (`size_5_2`, `size_13_1`, `size_25_2`)**: 한쪽 점수가 명확히 높아 기대 정답과 일치(`PASS`). `size_25_2`의 부동소수점 오차(`52.899999999999986`)는 `EPSILON = 1e-9` 비교로 정상 판정.
- **실패 3건 (`size_5_1`, `size_13_2`, `size_25_1`)**: `Cross`와 `X` 점수가 동일하여 `UNDECIDED` 판정을 받았으며, 정답이 한쪽으로 지정된 `expected`와 불일치하여 `FAIL`로 집계됨.

### 3.3 크기별 MAC 연산 성능 및 시간복잡도 `O(N²)`
| 바둑판 크기 (N×N) | 총 연산 횟수 (N²) | 평균 시간 (ms, 10회) | 3×3 대비 연산량 배율 |
| :--- | :---: | :---: | :---: |
| **3×3** | 9 | 0.0006 ms | 1.0배 |
| **5×5** | 25 | 0.0012 ms | 2.8배 |
| **13×13** | 169 | 0.0059 ms | 18.8배 |
| **25×25** | 625 | 0.0186 ms | 69.4배 |
- 행렬 한 변이 `N`일 때 전체 원소 수는 `N²`이므로 연산 횟수와 실행 시간이 `N²`에 비례하여 증가하는 **`O(N²)`** 시간복잡도를 가집니다.

## 4. 새 라벨 확장 절차 (매핑 · 판정 · 테스트 · 문서화)
현재 표준 라벨은 `Cross`와 `X` 두 가지이며, 새로운 도형 라벨(예: 원형 `Circle`)을 추가할 때는 아래 4단계 절차를 따릅니다.

1. **매핑 규칙 확장 (`main.py` 정규화 테이블 등록)**
   - `LABEL_ALIASES` 사전에 입력 별칭과 표준 라벨을 추가합니다. (예: `"o": "Circle", "circle": "Circle"`)
   - `SUPPORTED_LABELS` 튜플에 `"Circle"`을 추가하여 필터 로드 시 필수 라벨 검증을 자동화합니다.
2. **다중 라벨 판정 흐름 확장 (`judge_multi_scores` 연결)**
   - 2개 라벨 전용 `judge_scores` 대신 구현된 `judge_multi_scores(scores_by_label, tie_label)`를 호출합니다.
   - 모든 등록 라벨의 MAC 점수를 내림차순 정렬한 뒤, **1위와 2위 점수 차이가 `EPSILON(1e-9)` 미만이면 동점(`UNDECIDED`)**, 이상이면 1위 라벨을 최종 판정합니다.
3. **데이터 및 테스트 케이스 작성·검증**
   - `data.json`의 `filters.size_N`마다 새 라벨 필터 행렬을 추가하고, `patterns`에 **① 정상 일치 케이스(`PASS`)**, **② 타 라벨과 동점 케이스(`UNDECIDED -> FAIL`)**, **③ 행렬 크기 불일치·미등록 라벨 오류 케이스(`ERROR -> FAIL`)**를 작성해 검증합니다.
4. **문서화 업데이트**
   - `README.md`의 지원 라벨 목록과 `data.json` 스키마 예시, 테스트 결과 요약을 갱신합니다.

## 5. CPU vs NPU 아키텍처 및 병목 지점 비교
행렬 크기 `N`이 커질 때 범용 CPU와 AI 전용 반도체 NPU의 처리 구조 및 병목 지점은 다음과 같이 다릅니다.

| 비교 항목 | CPU (범용 중앙처리장치) | NPU (AI 전용 신경망 처리장치) |
| :--- | :--- | :--- |
| **연산 처리 방식 (직렬 vs 병렬)** | 소수의 고성능 코어가 `for` 반복문을 순차적(**직렬**)으로 실행하여 `N²` 증가 시 루프 지연 발생 | 수천 개의 MAC 연산기(Systolic Array 등)가 행렬 전체를 한 번에 동시(**병렬**) 계산 |
| **연산 병목 (Compute Bottleneck)** | 명령어 인출·해독 및 곱셈(`MUL`)·덧셈(`ADD`)·메모리 기록을 반복하는 **폰 노이만 제어 오버헤드**가 병목 | 곱셈과 누산을 단일 클럭에 동시 수행하는 **전용 MAC 하드웨어 회로**로 연산 병목 해소 |
| **메모리 병목 (Memory Bottleneck)** | 메인 메모리(DRAM) 대역폭 한계(Memory Wall) 및 2D 비연속 접근 시 **캐시 미스(Cache Miss)** 빈발 | 온칩 고속 스크래치패드 메모리(SRAM) 데이터 재사용과 **1D 연속 메모리 배치**로 이동 병목 최소화 |

## 보너스 문제
메뉴 **`3`번(`[보너스] 패턴 생성 및 1D 최적화 비교`)**에서 자동 패턴 생성과 1차원 평탄화 성능 비교를 실행할 수 있습니다.

### 1) 보너스 구현 요약

### 3) 대규모 패턴(`N >= 1000`) 메모리·시간 추정치 및 우선순위 최적화 가이드
파이썬 기본 자료구조(`list[list[float]]`, 원소당 약 28~36 Bytes 포인터·객체 오버헤드 포함) 기준 대규모 `N`에서의 추정치입니다.

| 패턴 크기 (`N`) | 총 연산 횟수 (`N²`) | 2D 리스트 메모리 추정 (패턴+필터 2개) | 순수 파이썬 루프 예상 시간 | 1D 평탄화(`to_1d`) 효과 |
| :--- | :---: | :---: | :---: | :---: |
| **`N = 1,000`** | $1.0 \times 10^6$회 | 약 56 ~ 72 MB | 약 30 ~ 60 ms | 행 포인터 제거로 메모리 절감 및 루프 단축 |
| **`N = 5,000`** | $2.5 \times 10^7$회 | 약 1.4 ~ 1.8 GB | 약 0.8 ~ 1.5 초 | 캐시 지역성 향상으로 지연 완화 |
| **`N = 10,000`** | $1.0 \times 10^8$회 | 약 5.6 ~ 7.2 GB (메모리 한계 주의) | 약 3.5 ~ 6.0 초 | 대용량 할당 시 메모리 단편화 및 GC 부담 감소 |

**▶ 대규모 `N` 처리를 위한 단계별 우선순위 최적화 가이드**
1. **1순위 (메모리 레이아웃 최적화 — 1D 평탄화 및 스트리밍)**: 2D 중첩 리스트를 제거해 1D 연속 배열(`to_1d`)로 다루고, 초대형 행렬은 행 단위 청크(Chunk)로 나누어 최대 메모리 점유량을 제한합니다.
2. **2순위 (자료형 경량화 및 벡터화)**: 파이썬 `float` 객체 대신 연속 버퍼(`array('d')` 또는 NumPy `float32`/`int8` 양자화)를 사용해 메모리를 최대 1/8로 줄이고 SIMD 벡터 연산을 적용합니다.
3. **3순위 (캐시 타일링 및 NPU 병렬 가속)**: 데이터를 L1/L2 캐시 크기에 맞춘 블록(Tiling) 단위로 분할해 메모리 병목을 줄이고, 최종적으로 NPU의 병렬 MAC 어레이로 연산을 오프로드합니다.
